# FABLE-CARRYOVER-CHECK: the prompt for the carry-over auditor

Use it after the move, in the first session of the NEW Claude account on the NEW repo, on a Fable agent. Paste the box as your message. About 15 minutes. You answer 2 questions (repo private? style preference?). Before the move, the old repo runs `python3 migration-setup/make_manifest.py` once more (after the last migration doc is committed) and commits `MANIFEST.json` on `main`.

```

Reading and dry runs only: never print, read or open any key, token or key dataset; never generate or render video; never edit a tracked file; never force-push or open a pull request. Do not fix anything, only report. A step you cannot do is NOT VERIFIED with the reason. Answer in my i-have-adhd style if active.

1. READ migration-setup/README.md and every file it links.
2. RUN `python3 migration-setup/verify_manifest.py --kaggle` (`--skip-env` only outside a session). Copy the table. A MISSING or CHANGED file is P0. If gh fails use the GitHub MCP tools and ask me "Is the repo private?" (USER-CONFIRMED). `main` must exist: `gh api repos/OWNER/REPO/branches/main --jq .name`. Rules: `gh api repos/OWNER/REPO/rulesets --jq length` and `.../branches/main/protection`; 403 "Upgrade to GitHub Pro" means no rules exist. N must equal `counts.lessons_active` in MANIFEST.json (104 at the moment of the move; use the manifest's number, it changes when lessons are added). C. Gaps ranked P0 (blocks work: files lost, repo public, no Kaggle access, main missing), P1 (works but degraded: style missing, branch rule), P2 (cosmetic). Each: one line, then "Fix: ..." in one line.
D. NOT VERIFIED: what and why.
E. Cleanup reminders: copy the list from migration-setup/REVOKE-AND-SECURITY.md word for word, add: delete the vault datasets (gemini-key, kagglegpu1, kagglegpu2) once the keys live in the new environment; revoke the old Kaggle tokens; disconnect the old GitHub connection from the old Claude account. Mark each DONE or OPEN.
```
